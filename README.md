# Memology

Многопользовательская карточная игра с мемами: читающий зачитывает ситуацию,
остальные тайно выбирают подходящий мем из своей руки, читающий выбирает лучший.

- Игра: https://heydarovmu-cmd.github.io/Memology/ (корень ведёт на `memology.html`)
- Админка контента: `memology-admin.html` (только для админа, вход по почте и паролю)
- Предпросмотр всех экранов без базы: `memology.html?preview`

Сборки нет — это обычные статические файлы для GitHub Pages. JavaScript написан
ES-модулями, браузер загружает их как есть.

## Структура

```
index.html               переадресация на игру
memology.html            разметка игры
memology-admin.html      разметка админки
css/
  base.css               общие токены темы Doodle Notebook и основа
  game.css               стили игры
  admin.css              стили админки
js/
  config.js              адрес Supabase, ключ, константы игры, аватары
  shared/dom.js          $(), esc(), toast(), делегирование кликов
  game/
    main.js              точка входа: связывает кнопки (data-action) с действиями
    controller.js        действия игрока, реакция на обновления, обязанности хоста
    rules.js             правила игры — чистые функции без DOM и сети
    screens.js           отрисовка экранов
    ui.js                экраны, окна, меню, просмотр мема
    sync.js              realtime-подписка, опрос, отсев устаревших версий комнаты
    api.js               все запросы к Supabase
    storage.js           localStorage: сессия, кэш контента, id устройства
    state.js             локальное состояние вкладки
    random.js            генератор с зерном, код комнаты
    preview.js           режим ?preview
  admin/
    main.js              админка
    auth.js              вход админа (Supabase Auth)
    sql.js               SQL таблиц и закрытого доступа
    import.js            разбор CSV / Excel / OCR — чистые функции
tests/
  unit/                  правила игры и разбор файлов (node --test)
  e2e/                   сценарии в браузере: несколько игроков против модели сервера
```

Кнопки в разметке не вызывают функции напрямую: у них есть `data-action="имя"`,
а `main.js` сопоставляет имя с обработчиком. Всё, что пришло от игроков или из
базы, вставляется в HTML только через `esc()`.

## Как устроена партия

Состояние комнаты — один JSON в таблице `rooms` (колонки `code`, `data`).
Фазы: `lobby → reader → picking → judging → result → … → end`.

- **Хост** (`hostIdx`, по умолчанию создатель) запускает игру и следующие раунды,
  переводит раунд к голосованию, когда все сдали мемы, пропускает раунд, если
  ушёл читающий, и заканчивает игру, если игроков осталось меньше трёх.
  Если хост выходит через меню, управление переходит следующему игроку.
- Переход к голосованию дублирует читающий: порядок карт на столе и ситуации
  считаются генератором с зерном комнаты (`seed`), поэтому повторная запись того
  же шага ничего не меняет.
- Ответы сервера могут приходить не по порядку. `sync.js` сравнивает «прогресс»
  комнаты (раунд, фаза, число сданных мемов) и отбрасывает устаревшие версии.
- Место за столом закреплено за устройством (`cid`). Если двое заняли одно место
  одновременно, второй автоматически пересаживается на свободное.
- Игрок, вошедший в последний момент, когда игра уже стартовала, получает
  сообщение «Игра уже идёт» — в партии участвуют только получившие руку.

## Доступ админа

Менять мемы и ситуации, загружать и удалять картинки, читать предложения игроков
может только админ. Игроки (анонимно) читают активные мемы и ситуации и отправляют
предложения. Это проверяет сам Supabase (row level security), а не страница.

Настройка один раз:
1. Supabase → Authentication → Users → **Add user** → почта и пароль,
   галочка «Auto Confirm User».
2. Открыть `memology-admin.html`, войти с этими данными.
3. Админка покажет SQL, где уже подставлен твой id: скопировать, выполнить в
   Supabase → SQL Editor, вернуться и нажать «Проверить снова».

SQL создаёт таблицу `admins` и функцию `is_admin()`, удаляет старые правила,
разрешавшие запись всем, и ставит новые (`js/admin/sql.js`). Повторный запуск безопасен.
Добавить второго админа: `insert into public.admins (user_id) select id from auth.users where email = '…';`

Шестерёнка на главном экране игры видна только в браузере, где админ вошёл в
админку, и ведёт в неё. Игра всегда работает анонимно, даже в браузере админа.

## Серверная часть (Supabase)

Таблицы `memes`, `situations`, `suggestions` и правила доступа создаёт SQL из админки
(кнопки «SQL для новой базы» и SQL первого входа). Для игры дополнительно нужны таблица `rooms` и две
функции; их исходник хранится только в Supabase. Клиент рассчитывает на такой контракт:

- `rooms (code text primary key, data jsonb)` с включённым realtime;
  комнаты старше суток удаляются.
- `patch_room(p_code text, p_paths jsonb) returns jsonb` — под блокировкой строки
  для каждого ключа `"a/b/c"` делает `jsonb_set(data, '{a,b,c}', value, true)`
  и возвращает новое `data`. Создаётся только последний недостающий ключ.
- `play_card(p_code text, p_player text, p_index int) returns jsonb` — атомарно
  переносит `hands[p_player][p_index]` в `submissions[p_player]`, на его место
  кладёт верхнюю карту `deck` (если колода пуста — рука укорачивается) и возвращает `data`.

Тесты используют модель этого контракта (`tests/e2e/fake-backend.mjs`). Если
функции на сервере поменяются — обновите и модель.

## Тесты

```
npm install
npx playwright install chromium
npm test            # всё
npm run test:unit   # только правила и разбор файлов (секунды)
npm run test:e2e    # сценарии в браузере (несколько минут)
```

Сценарии: полная партия, ничья и дополнительные раунды, конец колоды, обновление
страницы на любой фазе, проверки входа, одновременный вход, вход в момент старта,
выход из лобби и посреди игры, уход хоста, имена с HTML, устаревшие ответы
сервера, случайные задержки сети, двойные нажатия, ошибка сети, предложения,
работа без базы, совпадение кода комнаты, предпросмотр, админка: вход, первая
настройка, шестерёнка только у админа, закрытая база для игроков.

GitHub Actions запускает тесты на каждый pull request (`.github/workflows/tests.yml`).

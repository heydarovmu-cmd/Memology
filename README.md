# Memology

Многопользовательская карточная игра с мемами: читающий зачитывает ситуацию,
остальные тайно выбирают подходящий мем из своей руки, читающий выбирает лучший.

- Игра: https://heydarovmu-cmd.github.io/Memology/ (корень ведёт на `memology.html`)
- Админка контента: `memology-admin.html` (только для админа, вход по почте и паролю)
- Предпросмотр всех экранов без базы: `memology.html?preview`

Сборки нет — это обычные статические файлы для GitHub Pages. JavaScript написан
ES-модулями, браузер загружает их как есть.

## Структура

```
index.html               переадресация на игру
memology.html            разметка игры
memology-admin.html      разметка админки
css/
  base.css               общие токены темы Doodle Notebook и основа
  game.css               стили игры
  admin.css              стили админки
js/
  config.js              адрес Supabase, ключ, константы игры, аватары
  shared/dom.js          $(), esc(), toast(), делегирование кликов
  game/
    main.js              точка входа: связывает кнопки (data-action) с действиями
    controller.js        действия игрока и реакция на обновления комнаты
    rules.js             правила игры — чистые функции без DOM и сети
    screens.js           отрисовка экранов
    ui.js                экраны, окна, меню, просмотр мема
    sync.js              realtime-подписка, опрос, отсев устаревших версий комнаты
    api.js               все запросы к Supabase (функции mg_*)
    storage.js           localStorage: сессия и секрет устройства
    state.js             локальное состояние вкладки
    random.js            случайный id устройства
    preview.js           режим ?preview
  admin/
    main.js              админка
    auth.js              вход админа (Supabase Auth)
    sql.js               подстановка id админа в supabase/setup.sql
    import.js            разбор CSV / Excel / OCR — чистые функции
supabase/
  setup.sql              вся серверная часть: таблицы, права, логика игры
tests/
  unit/                  правила отображения и разбор файлов (node --test)
  db/                    логика игры и права доступа на настоящем Postgres
  e2e/                   сценарии в браузере: несколько игроков против того же Postgres
```

Кнопки в разметке не вызывают функции напрямую: у них есть `data-action="имя"`,
а `main.js` сопоставляет имя с обработчиком. Всё, что пришло от игроков или из
базы, вставляется в HTML только через `esc()`.

## Как устроена партия

Партию ведёт сервер: раздачу, колоду, ходы и подсчёт очков делают функции
`mg_*` в Supabase (`supabase/setup.sql`). Браузер игрока только показывает
состояние и отправляет ходы, поэтому подсмотреть чужие карты нельзя даже через
инструменты разработчика.

Что видит игрок:
- открытое состояние комнаты `rooms.data`: фаза, игроки и очки, ситуация раунда,
  кто уже сдал мем (`submitted`), карты на столе — без авторов до решения судьи,
  число карт в колоде;
- свою руку и, когда он читающий, две ситуации на выбор — через `mg_view`,
  только по секрету своего устройства (`mg_cid` в localStorage).

Что игрок не видит: каталог мемов и ситуаций, колоду, чужие руки, ситуации
читающего, авторов мемов до голосования. Всё это лежит в `room_secrets`, куда у
игроков нет доступа. Весь каталог видит только админ — в админке.

Фазы: `lobby → reader → picking → judging → result → … → end`.

- Хост запускает игру и следующие раунды. Если он выходит, управление переходит
  следующему игроку. Остальные переходы сервер делает сам: все сдали мемы — стол,
  ушёл читающий — раунд пропускается, осталось меньше трёх — конец игры.
- Каждый ход выполняется под блокировкой строки комнаты, поэтому двойные нажатия
  и одновременный вход не ломают партию.
- Ответы могут приходить не по порядку. `sync.js` сравнивает «прогресс»
  комнаты (раунд, фаза, число сданных мемов) и отбрасывает устаревшие версии.
- Вошедший в момент старта либо успевает сесть и получает руку, либо видит
  «Игра уже идёт» — третьего не бывает.

## Доступ админа

Менять мемы и ситуации, загружать и удалять картинки, читать предложения игроков
может только админ. Игроки могут только отправить предложение. Это проверяет сам
Supabase (row level security), а не страница.

Настройка один раз:
1. Supabase → Authentication → Users → **Add user** → почта и пароль,
   галочка «Auto Confirm User».
2. Открыть `memology-admin.html`, войти с этими данными.
3. Админка покажет SQL (`supabase/setup.sql`, где уже подставлен твой id):
   скопировать, выполнить в Supabase → SQL Editor, вернуться и нажать «Проверить снова».

Тот же SQL обновляет базу после новой версии игры: если серверная часть устарела
(`mg_version()` меньше, чем ждёт `js/admin/sql.js`), админка сама покажет его
снова, а игроки до обновления увидят «Игра обновляется». Повторный запуск безопасен.
Добавить второго админа: `insert into public.admins (user_id) select id from auth.users where email = '…';`

Шестерёнка на главном экране игры видна только в браузере, где админ вошёл в
админку, и ведёт в неё. Игра всегда работает анонимно, даже в браузере админа.

## Тесты

```
npm install
npx playwright install chromium
npm test            # всё
npm run test:unit   # правила и разбор файлов (секунды)
npm run test:db     # серверная логика и права на Postgres
npm run test:e2e    # сценарии в браузере (несколько минут)
```

Для `test:db` и `test:e2e` нужен установленный PostgreSQL (`initdb`, `pg_ctl`,
`psql`): тесты поднимают временную базу с заглушкой Supabase
(`tests/db/supabase-shim.sql`) и выполняют на ней настоящий `supabase/setup.sql`.

Сценарии: полная партия, ничья и дополнительные раунды, конец колоды, обновление
страницы на любой фазе, проверки входа, одновременный вход, вход в момент старта,
выход из лобби и посреди игры, уход хоста, имена с HTML, устаревшие ответы
сервера, случайные задержки сети, двойные нажатия, ошибка сети, предложения,
устаревшая база, игрок видит только свои карты, предпросмотр, админка: вход,
первая настройка и обновление SQL, шестерёнка только у админа, закрытая база.
На Postgres отдельно: скрытые данные для анонима, сохранность карт за всю
партию, ротация читающего и ничьи, выходы игроков, конец колоды, права админа.

GitHub Actions запускает тесты на каждый pull request (`.github/workflows/tests.yml`).
